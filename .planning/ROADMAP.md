# Roadmap: dsh-stt-multi

## Overview

Плагин DeepSeek Harness для голосового ввода строится послойно: сначала каркас
плагина с регистрацией провайдера в DSH и smoke-тестом нативного бинаря в реальном
профиле, затем слой загрузки моделей (sha256-манифесты, зеркала), затем
end-to-end воркер локального Whisper с русским. На этой базе — мульти-инстансы
(несколько моделей в списке настроек) и последние движки (GigaAM v2 локально +
OpenAI-совместимый API). Каждый слой завершается проверяемым поведением в реальном
профиле DSH; release-hardening (npm-упаковка, матрица совместимости, публичный
GitHub) сворачано в конец фаз 3 и 5, а не выделено в отдельную фазу — бюджет
агента ограничен, отдельных фаз без требований избегаем.

## Phase Details

### Phase 1: Plugin Skeleton & Provider Registration
**Goal**: Плагин устанавливается в профиль desktop DSH и его движок виден и выбираем в родных настройках голосового ввода; самый рискованный интеграционный риск (нативный бинарь внутри Electron/ASAR) снят первым же smoke-тестом
**Depends on**: Nothing (first phase)
**Requirements**: PROV-01, PROV-02, PROV-03, QUAL-02
**Success Criteria** (what must be TRUE):
  1. После установки пакета в профиль desktop движок плагина появляется в списке настроек голосового ввода DSH — без правки кода приложения
  2. Пользователь выбирает движок в настройках; после перезапуска DSH выбор сохраняется (персистенция ядром DSH)
  3. Нажатие родной кнопки микрофона при выбранном движке плагина завершается событием транскрипции (допустим echo/stub-ответ) — собственных хоткеев и UI у плагина нет
  4. Нативный модуль sherpa-onnx-node загружается и конструирует распознаватель внутри реального профиля DSH (Electron/ASAR), что подтверждено smoke-тестом — не только в plain node

### Phase 2: Model Assets & Download Layer
**Goal**: Слой загрузки моделей работает сам по себе: модель выбирается — скачивается надёжно (зеркала, sha256, докачка) или подхватывается из ручной установки, с понятными сообщениями об ошибках
**Depends on**: Phase 1
**Requirements**: DL-01, DL-02, DL-03, DL-04
**Success Criteria** (what must be TRUE):
  1. При первом выборе модели она автоматически скачивается (HF с fallback на hf-mirror) в namespaced-директорию `~/.dsh/speech-to-text/<provider>/<model>/`
  2. Скачанные файлы проходят проверку по собственному sha256-манифесту (pinned revision); прерванная загрузка докачивается, публикация директории атомарна (нет полусобранных моделей)
  3. Пользователь может положить файлы модели в директорию вручную — модель работает без загрузки, хэш-проверка для неё пропускается
  4. При ошибке загрузки или запуска пользователь видит читаемое сообщение (кнопка теста модели даёт понятную диагностику, а не стек трейс)

### Phase 3: Whisper Worker End-to-End
**Goal**: Основная ценность продукта достигнута: пользователь диктует на русском в родную кнопку микрофона DSH локальным Whisper офлайн, из коробки, с приватностью и аккуратной памятью
**Depends on**: Phase 2
**Requirements**: STT-01, STT-02, STT-03, QUAL-01, QUAL-03
**Success Criteria** (what must be TRUE):
  1. Пользователь диктует на русском локальным Whisper (tiny→large-v3-turbo) без сети после загрузки модели; текст появляется в чате DSH
  2. Золотой набор ru+en аудио проходит регрессионный тест качества (транскрипт корректен; decoder-параметры — language tokens, tailPaddings — не ломают вывод)
  3. После установки плагина и выбора дефолтной модели диктовка работает сразу (модель по умолчанию выбрана по качеству/размеру и скачивается при первом использовании)
  4. Аудио не покидает устройство: локальный движок не делает сетевых запросов при распознавании (проверено трассировкой)
  5. Память распознавателя освобождается (`free()`) при выгрузке/смене модели — RSS возвращается к базовому уровню

### Phase 4: Multi-Instance Model List
**Goal**: Дифференциатор «как в Handy»: несколько моделей стоят в списке настроек DSH одновременно, каждая со своим конфигом, включая квантованные/turbo варианты и произвольные sherpa-совместимые модели пользователя
**Depends on**: Phase 3
**Requirements**: MULTI-01, MULTI-02, MULTI-03, CUSTOM-01
**Success Criteria** (what must be TRUE):
  1. Несколько записей плагина в `cordis.patch.yml` дают несколько моделей одновременно в списке настроек голосового ввода DSH; переключение между ними не требует перезапуска и не даёт конфликтов (двухинстансовый тест: пути, память)
  2. Каждая модель настраивается per-instance: язык (auto/ru/en…), threads, precision — как у штатного плагина
  3. Каталог моделей содержит квантованные (int8/q5) и turbo-варианты Whisper — их можно выбрать и они скачиваются и работают
  4. Пользователь подключает произвольную sherpa-совместимую модель через `modelDirectory` — она появляется в списке и работает без загрузки
**Plans**: TBD

### Phase 5: GigaAM v2 & API Providers
**Goal**: Полный набор провайдеров v1: лучший локальный RU-специалист GigaAM v2 (готовый ONNX-пакет, без конверсии) и OpenAI-совместимый облачный провайдер — плюс лицензионная проверка и релизная упаковка (npm pack, публичный GitHub)
**Depends on**: Phase 4
**Requirements**: GIGA-01, GIGA-02, API-01, API-02
**Success Criteria** (what must be TRUE):
  1. Пользователь диктует на русском локальным GigaAM v2 (готовый ONNX-пакет k2-fsa, `modelConfig.nemoCtc`) — офлайн, с золотым ru-аудио тестом качества против эталонного транскрипта
  2. Лицензия GigaAM v2 проверена и зафиксирована до публичного релиза (ограничения на распространение отражены в упаковке репозитория/npm)
  3. Пользователь настраивает OpenAI-совместимый провайдер (`/audio/transcriptions`, Groq/OpenAI/…): baseURL + ключ per-instance; диктовка через облако работает
  4. Облачные движки явно помечены в списке настроек (аудио покидает машину); по умолчанию всё локально
**Plans**: TBD
